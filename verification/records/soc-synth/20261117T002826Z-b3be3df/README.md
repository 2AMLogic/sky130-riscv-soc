# soc_top resynthesis: the dead `per_gnt` tie-off removed, 2026-11-17

Resynthesis for issue #182 — the last `rtl/` leftover of the ISRAM_1RW
removal (#172): `soc_fabric`'s `per_gnt` has been a driver with no reader
since #181 deleted `obi_xbar`'s `*_gnt_i` ports. Because it kept its public
RTL wire name, Yosys retained a `sky130_fd_sc_hd__conb_1` tie-high whose only
consumer was that wire — the dead signal was costing one real tie cell in the
signoff netlist, not zero. The same change regains a behavioural
alternate-depth lint pass (`ISRAM_AW=10 DSRAM_AW=10`, no `ISRAM_1RW`) in
`verification/tools/lint_rtl.sh`, stops `rtl/README.md` presenting the depth
parameters as a free knob, and rewrites `obi_bench.py`'s grant paragraph to
the fabric's post-#181 contract. `rtl/soc_sram_i.sv` is deliberately
untouched (contended by #147/#169/#170, and nothing here needs it).
Append-only; supersedes record `20261115T205309Z-5e9335c`. **Pre-route
synthesis only** — no placement, no routing, no STA, so this record makes
**no Fmax or timing claim**.

## What was run

`scripts/synth-soc.sh` **twice** with the pinned klt 0.9.1
(`uvx --from "klayout-tools==0.9.1" klt`; the host's dev build was not
used), first on unmodified `main @ 2814179` (a detached scratch worktree;
baseline criterion), then on this commit's tree. `synth_request.json`,
`synth_result.json` and `synth_soc_top.ys` here are the klt request, its
unedited JSON output and the Yosys script it ran; `synth_result_baseline.json`
is the unedited output of the baseline run, kept so the before figures are
auditable rather than asserted. The netlist is `netlist/soc_top_synth.v`,
sha256 `160672fe…` (`provenance.json`).

**Baseline control:** the baseline run reproduced `main`'s committed netlist
byte-for-byte (sha256 `e4592eca…` both) — the delta below is attributable to
this change alone, not the toolchain.

**Tool environment note:** klt synthesize deadlocks in Yosys' abc pass on
this host when `TMPDIR` is set to the loom sandbox path
(`/tmp/loom-nt/<uuid>`) — same as the two records this one follows; both
runs were made with `TMPDIR` unset.

## Verification run alongside

`verification/tools/lint_rtl.sh` passes in both forms (default, which now
includes the alternate-depth leg — `soc_fabric 1024 words` — and
`SRAM_MACRO_V=<macro .v>`, which correctly skips it: the macro build is
`AW=11` only, enforced at elaboration in `soc_sram_i.sv`). The leg
demonstrably bites: with a temporary depth-dependent expression sized for
the default depth (`a[31:ISRAM_AW+2]` into a 19-bit target), the script
fails with WIDTHTRUNC **only in the alternate-depth leg** and the default
pass still passes; the temporary edit was reverted before the run recorded
here. `verilator --lint-only -Wall -Wno-MULTITOP --top-module soc_fabric`
no longer reports `per_gnt` as `UNUSEDSIGNAL`; the remaining hits are the
pre-existing unused bus bit slices and the three deliberate `soc_sram_i`
port-1 ports (`clk1`, `csb1`, `addr1`, unused at `USE_PORT1=0`), all out of
scope. `make -C verification xbar periph boot soc soc-negative` passes
unchanged (xbar: 9 tests; no test added, removed or skipped).
`verification/tools/tests/test_lint_rtl.sh` passes. `make -C verification
soc-gate` passes on the regenerated netlist and the gate-level banner
transcript equals the golden (`soc-gate.log.txt`). All three `signoff.yml`
legs reproduce locally (`klt signoff --check`: manifest report `match`,
item 1 pass, item 10 pass) against the regenerated `evidence/item1.json`
(new `soc_fabric.sv`/netlist digests) and manifest; `evidence/item10.json`
regenerated byte-identical (its input digest covers `attest/item10.json`,
which this change does not edit).

## Out of scope here, noted

`records/soc-sta-preroute/` and `records/soc-pnr/` bind the superseded
netlist and so describe a netlist one change old (the record this one
supersedes already carried that caveat). This change is logic-identical
modulo one dangling tie cell (`sequential_area_um2` identical), so no
recorded timing claim moves in the unsafe direction, but re-running
pre-route STA and P&R on the current netlist is outstanding work, not
covered here. Global route on `soc_top` still fails (GRT-0116,
macro-interior congestion); nothing in this change claims to fix that.
